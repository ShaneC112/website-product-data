- **Status:** Canonical learning detail.

## Learning

## Vision-AI room prompts must use qualitative visual anchors instead of CAD numerical dimensions

When Vision-AI generates CAD-style numerical dimensions (e.g., `6.5m x 5.0m with 2.7m ceiling height`, `0.9m wide, left-hand swing inward`, `0.3m supporting beam`), FLUX diffusion models treat these numerical metrics as spatial/blueprint noise. This causes non-deterministic room rendering across seeds, including empty or unfurnished rooms in some seeds despite identical prompts.

### Root Cause

The Black Forest Labs (BFL) FLUX T5 text encoder is trained on natural descriptive image captions. Exact CAD measurements consume spatial conditioning tokens and trigger blueprint or technical drawing weights without providing visual features that FLUX can render into physical objects.

### Context & Intent

Room prompts (`roomDescription` generated via `generateRoomPrompt` in `roomAnalysis.ts`) are cached per template/room and reused across all product colour variants (e.g. carpet colourways in the same room) to maintain room consistency.

### Durable Invariant

Room prompts generated by Vision-AI must focus on qualitative visual architectural anchors (e.g., "generous master bedroom with tall ceilings, large north-facing window as main light source, wide open archway on the east wall") rather than numerical CAD measurements, exact dimensions, or door swing directions. Visual anchors establish room consistency across sibling product colours while eliminating text-encoder noise and preserving token budget for furniture.
